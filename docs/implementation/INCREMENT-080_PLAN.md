## Dependency and gap
Runbook S102.2 requires deletion **only** from positively owned ledger paths, followed by independent Android remote filesystem and MediaStore reconciliation. Increment079 checked the persisted whole-job ledger but deliberately returned `canDelete=false` due missing real Facebook/TikTok provider certification. The current ADB client has Sync RECV for exact bytes and read-only MediaStore probes, but no bounded Sync STAT for post-delete remote existence. Without one, an eventual deleter could falsely call cleanup complete based on shell ACK, stale MediaStore, or a synthetic DB record.

## Scoped implementation
1. `packages/devices/src/index.ts`: add `AdbClient.statOwnedStage` using Android ADB Sync v1 `STAT` (non-destructive), requiring a `scoped(beforeDispatch)` trusted fence. Validate serial, jobId, 0–31 ordinal, 32-hex nonce, allowlisted extension and positive expectedBytes; derive the remote path **exclusively** via `ownedStageLocation`. Strictly decode 16-byte `STAT` frames (mode/size/mtime), fail closed on malformed packet, nonregular mode, invalid/nonzero missing fields, premature close, unknown response or cancellation. Return `REMOTE_PRESENT_OBSERVED` with observed bytes/byte-match or `REMOTE_ABSENT_OBSERVED`, both `canDelete:false/canMarkClean:false`. This is a remote filesystem observation, **not** proof a delete occurred or MediaStore was reconciled.
2. `packages/devices/src/owned-cleanup-reconcile.ts`: pure `assessOwnedCleanupReadback` classifier binding a fenced remote STAT observation and independent `probeOwnedStageMediaStore` observation for one exact frozen-owned slot; missing remote + NOT_INDEXED becomes `ABSENCE_CANDIDATE_UNCERTIFIED`, still no cleanup authorization. Present file, indexed row, ambiguous/unsupported probe, mismatched expected length or missing evidence stay `REVIEW_REQUIRED`/BLOCKED. All output redacted with `canDelete/canMarkClean/canRetry/canDispatch=false`. No input argument can supply provider proof or cleanup capability.
3. `tests/fixtures/adb-server.ts`: extend local fake ADB server with bounded Sync STAT path parsing and controllable present/missing/invalid protocol responses. No destructive fake shell action.
4. `packages/devices/src/devices.test.ts`: protocol tests for valid present/missing, wrong size/type/malformed data, invalid path/nonce/extension, unscoped transport, revoked fence, cancellation, no shell `rm`, path is generated canonical only.
5. `packages/devices/src/owned-cleanup-reconcile.test.ts`: pure MediaStore/remote readback matrix, fail-closed invalid/forged statuses and no-rights/read-only checks.

## State/fault/acceptance matrix
Canonical owned remote path present + matching bytes -> REMOTE_PRESENT_OBSERVED, cleanup not completed. Canonical path absent + MediaStore NOT_INDEXED -> ABSENCE_CANDIDATE_UNCERTIFIED, **NOT** verified delete/provider success. Missing file with indexed row -> REVIEW_REQUIRED. Unknown Android Sync/MediaStore, stale owner fence, mismatched bytes, malformed response -> BLOCKED/reject, no retry. No call to `rm`, MediaStore delete, PC source deletion, posts or comments; no journal mutation.
