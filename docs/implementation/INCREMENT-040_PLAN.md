## Scope, threat model, and ordering

Missing: a reusable pure, deterministic comparator for future live P10 evidence. The current public `jobPreflight` is intentionally persisted-only and cannot observe Android profiles, real app state, verified target/account/network or staging file bytes.

1. Add `packages/domain/src/preflight.ts`, exported through domain index, with a typed `JobPreflightEvidence` input (immutable job/snapshot/hash, runtime DeviceRecord, app definition/profile, exact trusted DEVICE_TEST receipt, time-correlated media evidence, account/target/network observations and checked clock) and a **redacted bounded** `JobPreflightAssessment`: ordered named blocker codes, `evidenceConsistent` for comparative diagnostics, **`dispatchAuthorized: false` by type and literal**. The helper never calls ADB/filesystem/DB, cannot assume observation provenance, and cannot grant an execution lease.
2. Verify immutable snapshot/workflow and content ID, job shape and PREFLIGHT state, app identity/package and supported-profile designation, device ID/identity/enabled, current connected identity-verified transport with valid observed timestamps, current JOB ownership window, exact app profile on the same device and matching receipt kind/hash/profile/user confirmation.
3. Require explicit target/account/network observation for publish-capable jobs. Inspect ordered pinned media IDs/hashes/state with a bounded budget and no duplicate/missing media. **Text-only posts are valid** only when the app declares text support and the frozen job contains non-empty text; do not require a synthetic media attachment for text-only content. Media staging must be checked by the future trusted host; this pure helper only compares supplied evidence.
4. Validate clock skew, stale/future observations including transport freshness, malformed hashes, omitted/extra media. Do not echo raw filenames, caption, app credentials, source paths, ADB serials or target identity values in blockers. Never mark a provider posting result, job state or stored DB record.
5. Unit tests for synthetic consistent matched bundle (comparison succeeds but dispatch stays false), state/hash/profile/receipt/device/transports/lease/time/target/account/network failures, media ordering/duplicate/stale/changed, text-only and unsupported-text, immutable input, redaction and bounded conditions. No profile fixture is real device certification.
6. Run hosted `pnpm check`, Chromium `pnpm test:ui`, `pnpm check:plan` on Ubuntu and Windows. Fix exact failures, then record result and evidence, commit separate results/progress/checkpoint to `feat/studio-workspace` only. Do not change `main`, force refs, ship installer, or claim full P11 acceptance.
