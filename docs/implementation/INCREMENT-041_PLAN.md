## Scope
Current job snapshots hold pinned media hash metadata, but a future executor must rehash host file **actual bytes**, not trust the cached SQLite state. This increment implements private, read-only verification of an already registered, host-approved media selection. It does not stage files on Android, publish posts, create job leases or expose raw file paths to renderer/HTTP.

1. Define a PRIVATE-only `JobMediaPreflightPlan` contract (job revision/hash plus ordered asset id, pinned hash/bytes and `MediaAssetBinding` host grant). Do not add it to `StudioApi`, public command registry, preload or any UI object.
2. Implement `StudioDatabase.jobMediaPreflightPlan(jobId, hostId)`: validate pinned immutable job hash/Process, active scheduled/queued/preflight state, no external effects, bounded distinct snapshot asset IDs, exact pinned asset hash/byte metadata and a unique READY source binding on the current host with matching observed hash. No writes or SQL migrations; source/file paths only in private returned object. Text-only jobs return an empty plan without claiming content certification.
3. Add internal DB-worker command `job.mediaPlan` only, wired through `apps/desktop/src/host/internal.ts`; public `dispatch` must reject it. `HostMediaService.inspectJobMediaBytes(jobId)` calls that private plan, streams file fingerprints sequentially through host grants with existing canonical-path/symlink/host/size protections, finite per-file timeout, bounded concurrency and resource budget. After hashing, fetch the plan again and reject any changed job revision, source revision/binding/ledger/hash. No temporary writes, no source changes, no Android input.

Do not show `VERIFIED` for text-only or empty selection.
