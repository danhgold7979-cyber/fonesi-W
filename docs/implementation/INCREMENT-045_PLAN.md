## Missing link / invariants

The host-owned staged byte copy, remote-stage intent table, and fenced ADB Sync method exist independently. A trusted internal coordinator must join them in the correct order without turning an Android Sync ACK into a verified MediaStore item or a posted result.

1. Add a host-only `HostStageTransferService`, not registered in `StudioApi`, preload, renderer, HTTP dispatch or timer scheduler. Only a future private, certified JOB executor can invoke it. Inputs: already-claimed JOB lease/expected job revision/hash, exact device transport serial/generation and pinned asset ordinal. Enforce strict validation and no arbitrary file/remote paths.
2. Require local `HostMediaService.stageJobHostMedia(jobId)` to finish (actual byte/manifest verification) before any Android side effect; obtain private SQLite `job.mediaPlan` and check snapshot/asset order/bounds. Assert current `lease.assert` and `device.assertTransport`, then atomically `stage.prepare` to persist destination/nonce/claim generation. Refuse duplicates and stale scope.
3. Add read-only private `stage.assertClaim` to SQLite: assert same leased JOB, claim generation, job revision/hash, stage ownership and `TRANSFER_UNCERTAIN` phase. After `stage.beginAttempt` atomically persists uncertainty, a scoped `AdbClient` must call this check plus transport check before each Android operation/DONE. A DB/reconnect/lease failure after begin leaves uncertainty, never rolls back to INTENT, never automatically retries or removes remote contents.
4. Send via `AdbClient.scoped(fence).sendOwnedStage` with local path derived exclusively from app-owned data root, job ID, ordinal and allowlisted extension; send exact generated nonce/hash/bytes from the DB stage record. Assert response remote path/bytes/state exactly match committed intent. Only then `stage.syncAck` may persist `SYNC_ACK_UNVERIFIED`. Return a **redacted** private result (stage ID/job/ordinal/state, canDispatch:false), no private raw file path, hardware serial, caption or credentials.
5. Construct service in Electron main and loopback host with dynamic device adapter referencing current configured ADB; store it as a private HostServices member, **no public request routing**. No invocation on startup, schedule preview/apply, device scan, or user button. No social app actions.
6. Tests with real SQLite stage fixture and a fake ACK/failure transport adapter capturing ordered calls. Assert that durable INTENT and TRANSFER_UNCERTAIN precede any fake bytes; ACK stored only after matching confirmation; mismatch/failure/expired lease leaves uncertainty and a restart routes job to review; duplicate invocation cannot send again; unauthorized/stale transport/host and no-media do not begin, no public command exists.
7. GitHub source checks Ubuntu/Windows `pnpm check`, Chromium `pnpm test:ui` and `pnpm check:plan`, fix failures, record source commit, CI receipts and partial acceptance. No automatic real-device upload, MediaStore claim, main merge or installer publish.

It does NOT solve hardware-proven app identity/foreground, remote Android hash/MediaStore indexing and picker correlation, restart stage resolution, source cleanup, publish/comments/verification, Win10 physical USB/LAN or fleet 20→300 acceptance.
