## Dependency / actual gap

Increment069–071 binds a frozen Unicode comment item and its ordinal to a durable COMMENT INTENT and transports that exact body to a *trusted injected fixture adapter*. However S100.2 requires inspecting independent provider readback before any comment retry, particularly after timeout/restart. There is no real Facebook/TikTok provider adapter, trusted comment identifier or on-phone verification. An absent match is **not** proof the comment was never posted. Moreover, identical text at two frozen ordinals cannot be attributed to one ordinal from provider body alone.

## Fault/state matrix and limits

No/unknown match -> NEEDS_REVIEW (not safe retry). Multiple exact comments, duplicate observation/comment IDs or same frozen text across ordinals -> ambiguous/block. Untrusted/malformed/stale readback -> BLOCKED, no effect transition. One structurally exact candidate -> **UNCERTIFIED**, never CONFIRMED or allowed to retry. Existing INTENT and ATTEMPT_UNCERTAIN remain durable. Nothing touches real Android input or provider; no comment-only retry feature is enabled.

Maximum status `TESTED_S100_COMMENT_CANDIDATE_READBACK_NOT_ACCEPTED`. S100.2/AT-100 requires physical Windows10+Android USB/LAN, real account/target/post and independent provider observation. P11 S087/S095/S096/S097–S103, P12 apps, P13 20–300 fleet and P14 installer/release remain OPEN/NOT_RUN; whole-tool percent cannot be grounded from fixture tests.
